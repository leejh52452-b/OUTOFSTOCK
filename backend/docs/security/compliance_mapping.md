# 규정·기준 대응표 — 개인정보 안전성 확보조치 · 전자금융감독규정 · N²SF · BCBS 239

> 이 서비스는 전자금융업자도, 공공기관도, 은행도 아니다. 아래 표는 **"금융권 공기업이라면 무엇을 요구받는가"를 설계 기준으로
> 삼은 대응표**다. '반영'은 코드·시험으로 확인 가능한 것만 적었고, 범위 밖이면 '해당 없음'과 이유를 적었다.
> 조문은 2026-10-22 기준으로 확인했다(제13조 각 호는 2025.2.5 개정 기준 — 2026-11 금융보안원 특강 자료로 재확인). 운영 절차(사람이 하는 일)는 [`internal_management_plan.md`](internal_management_plan.md).

## 3. 국가망보안체계(N²SF) 가이드라인 1.0(2025.9) — 등급과 통제 영역

N²SF 는 업무정보·정보시스템을 **기밀(C)·민감(S)·공개(O)** 로 나누고 등급별로 차등 통제(통제 280여 개, 6개 영역: 권한·인증·분리·
격리·데이터·정보자산)를 적용하며, 제로트러스트를 보안대책 수립의 필수 기준으로 둔다. 이 서비스의 4단계 분류를 대응시키면:

| 이 서비스 등급 | 예 | N²SF 대응 | 적용 통제 |
|---|---|---|---|
| L1 공개 | 시세·뉴스·추천·용어 | O(공개) | 무결성(품질 게이트·출처·기준일) · 캐시 허용 |
| L2 내부 | 배치 기록·지표·역할 요청 | S(민감) 하한 | 관리자만 · 외부 비공개 |
| L3 개인정보 | 계정·지갑·원장·관심·학습·접속 기록 | S(민감) | FORCE RLS · 보관 기간 파기 · 열람 목적 기록 · 백업 암호화 |
| L4 민감·비밀 | 비밀번호 해시·토큰 해시·TOTP 비밀·채팅·외부 키 | C(기밀) 수준 통제로 취급 | 해시 또는 봉투 암호화 필수(시험이 강제) · 키는 DB 밖 · 접근은 시스템 문맥만 |

| N²SF 통제 영역 | 이 서비스 |
|---|---|
| 권한 | 기본 거부 정책 · 자격 + JIT · DB 계정 분리 · FORCE RLS |
| 인증 | 세션 매 요청 검증 · TOTP · 추가 인증 · 기기 인증서(관리) |
| 분리 | 망 4개(compose) · 앱 루프백(VM) · 서비스·배치·마이그레이션 계정 분리 |
| 격리 | 컨테이너(읽기 전용·capability 0) · systemd 샌드박스(홈 숨김·시스템 호출 제한) · egress 차단 |
| 데이터 | 분류 등록부 · 봉투 암호화 · 감사 체인 · 백업 암호화 · 가명 처리 |
| 정보자산 | SBOM · 해시 고정 의존성 · 데이터 사전·계보 자동 생성 |
