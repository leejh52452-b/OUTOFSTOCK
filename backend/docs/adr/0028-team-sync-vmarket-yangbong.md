## 맥락
팀이 화면 다섯 장을 고치고 기능 둘을 더했다. ① **모의투자**(`invest.html`) — 매주 월~금 한 시즌, 가상 종목 5개, 평일 09:00~15:00
30분마다 봉 하나 공개, 참가금(가상머니 100만 원~)으로 사고팔다 주말에 정산. ② **양봉이 주간 추천** — 홈 추천 카드를 '이번 주 양봉이가
고른 5종목'·'한 달 전 바구니 결과'로 바꾸고, 알고리즘(`yangbong_picks.py`)과 연결 예시(`api_example.py`)를 백엔드 몫으로 남겼다.
그 밖에 실습(원칙 매매 — 손절 반영·국내 실전 구간·8배속), 용어사전(문장 단위 풀이), 첫 접속 투자 유의 안내, 전 화면 '모의투자' 메뉴.

팀 시안의 모의투자는 **잔액·체결·정산을 브라우저 localStorage 에 두고, 시즌 파일(미래 봉 65개 포함)을 통째로 내려받는다.**
우리 서버에선 가상머니가 지갑·원장·복식부기로 묶여 있어(꾸미기 구매·송금), 그대로 옮기면 개발자 도구로 잔액을 고치거나
금요일 종가를 미리 보고 월요일에 사서 가상머니를 무한히 만들 수 있다.

## 결정
1. **모의투자는 서버가 정한다(서버 권위).**
   - 시즌 데이터는 DB(`vmarket_season`, 해시)에만. `GET /vmarket/season` 이 **서버 시계(한국시간)로 '공개된 봉'까지만** 잘라 준다 —
     진행 중 시즌의 장세(시나리오)·다음 시즌은 비공개, 끝난 시즌만 전체. `web/` 에 시즌 파일을 두지 않는다(정적 파일로 새지 않게).
   - 참가(`POST /vmarket/join`) = 참가 행 + 종목 5개 보유 행 + 지갑 출금(`vmarket_entry`, 분개 상대 `sys:vmarket_custody`)을 한 트랜잭션.
   - 주문(`POST /vmarket/order`) — 장중에만, **체결가 = 지금 공개된 마지막 봉 종가(서버)**. 화면이 본 봉 수(`bar`)가 서버와 다르면 409
     (새 봉이 나온 사이 옛 가격 체결 방지 — 팀 화면의 같은 확인을 서버에서도). 현금·보유 초과 거부, `Idempotency-Key` 재전송 1번,
     참가 행 `FOR UPDATE` 로 동시 주문 줄 세움. 잠금 순서는 지갑 규칙(계정 → 업무 행 → 지갑).
   - 정산 — 토요일 0시 이후 남은 주식을 종목마다 마지막 봉 종가로 팔고 최종 평가금액을 지갑으로(`vmarket_settle`, 멱등키).
     스케줄러 매일 00:05(놓친 주 포함 전부) + 화면이 주말에 `POST /vmarket/settle` 로 바로 요청. 같은 시즌은 한 번만(상태 + 원장 키).
   - 개인 표 3개 FORCE RLS(V019) · 탈퇴 시 삭제 · 정책 동작 `vmarket.trade`(기기 결속, 비상 차단 `vmarket`).
   - 시즌 파일 가져오기는 형식·가격(정수·시≤고·저≤종 범위·양수)·이름(화면 삽입 문자 금지) 검사 + SHA-256. **시작한 시즌(또는 참가자가
     있는 시즌)은 내용 변경 거부**, 저장 뒤 해시가 다르면 그 시즌을 쓰지 않는다. 시즌 11부터는 `run.py vmarket-import` · 금요일 18:00 경보.
2. **화면은 팀 시안 그대로, 데이터 출처만 바꾼다.** `invest.html` 은 같은 그리기 코드를 두 '출처'로 돌린다 — 우리 서버(`OOS.online`)면
   `/vmarket/*`, 파일로 열면(시안 모드) 팀 방식(시즌 파일·이 브라우저 기록 — 시안 전용 키). 시계는 서버 시각(`OOS.serverNow`, Date 헤더)의
   한국시간 — 다른 시간대 브라우저도 같은 시즌·봉. 새 봉 시각에 다시 묻고, 경계에서 엇갈리면 2초 뒤 한 번 더, 5분마다 조용히 확인.
3. **양봉이 주간 추천은 팀 알고리즘을 고치지 않는다.** `yangbong_picks.py` 원본을 그대로 두고 시험이 해시로 고정한다.
   우리가 채운 곳은 팀이 비워 둔 세 함수(데이터 적재·저장·불러오기)와 배치·API:
   - 데이터 = 분석 계층 `analytics.price_history`(KRX 전 종목 일별매매정보) — 코스피에 있던 날의 행만, 수정주가는 팀 방식 그대로
     (`Y.adjusted_close` — 원 종가 + KRX 등락률), 수정시가 = 시가 × 수정종가 ÷ 종가, 비교 지수 = `index_daily`(KOSPI).
   - 보통주: 팀은 KRX 종목기본정보(증권구분·주식종류)를 썼다. 우리 적재기는 그 API 를 받지 않아 같은 뜻의 코드·이름 규칙
     (끝자리 0 · 9로 시작하는 외국주권 제외 · 스팩·리츠·리얼티·인프라(투자회사)·'○호'(선박투자회사) 제외). 업종 = DART 업종코드 앞 3자리.
   - 배치는 **따라잡기형**(매일 08:55·23:55): 데이터가 들어온 '끝난 주'마다 없으면 고르고, 30일 지난 바구니를 채점. 금요일 확정치는
     KRX D+1 이라 토요일 밤 또는 월요일 08:40 적재 뒤 — 월요일 장 시작(매수) 전에 나온다. 그 주 마지막 거래일 시세가 없거나
     후보가 150 미만(부분 적재·표본 DB)이면 고르지 않는다. 동시 실행은 advisory lock.
   - 초기 데이터 = 팀 백테스트 247주 CSV(첫 주부터 승률·누적 수익) — 팀 시험 1~3번과 같은 값(247주·136주·평균 +1.51%·+374만 원).
   - `GET /yangbong/weekly` = 팀 `api_example.weekly()` 와 같은 JSON(+ `source`·`model`), 공개 조회라 ETag/304·서버 캐시 10분.
     경로는 우리 규칙대로 `/yangbong/weekly`(팀 예시 `/api/yangbong/weekly` 대신 — 화면은 `OOS.api` 로 부른다).
4. **화면 병합 규칙(이번에도 같음)**: 팀 기준판(`4c63542`)·팀 최신판·우리 판의 3방향 병합 — 인라인 핸들러 → `data-on`, 값은 `textContent`/`esc()`,
   서버 값이 오기 전엔 예시 값을 실제처럼 보이지 않게(불러오는 중), 대비 4.5:1(주의 라벨·장세 칩·선택한 종목 탭의 상승색),
   첫 접속 안내는 브라우저 저장소(세션·30일) — 개인정보가 아닌 표시 설정.

## 결과
- 모의투자: 미래 봉·잔액·체결가를 화면에서 바꿀 길이 없다(시험: 공개된 봉까지만·옛 봉 409·재전송 1번·동시 주문 4개 중 1개만·정산 1번·
  원장/분개 대사). 화면은 팀 시안과 같고, 서버가 없으면 시안 모드로 그대로 돈다.
- 양봉이: 팀 시험 1~3번 통과 + 합성 시장(분할 종목·우선주·리츠·스팩·외국주권·코스닥·거래정지·한글날/추석 주)에서
  '실제(분할 없는) 가격으로 고른 답 = 우리 배치가 고른 답'. 실데이터 재현(2026-10-23 5종목)은 KRX 전 종목이 적재된 서버에서
  `run.py yangbong` 으로 확인한다.
- 위협 T-41(모의투자 조작)·T-42(추천 데이터 무결성) 추가 · 경로 147 → 153 · 정책 동작 28 → 29 · RLS 표 18 → 21.

## 남은 위험·한계
- 시즌 데이터(가상 주가)는 팀 생성기 산출물을 그대로 쓴다(형식·가격만 검사) — 생성 규칙의 통계적 타당성은 팀 몫. 시즌 11(2027-01-11 주)
  부터는 운영자가 파일을 넣어야 한다(없으면 그 주 참가 불가 · 금요일 경보 · `/admin/health` 의 `vmarket_next_season_missing`).
- 보통주 규칙은 이름·코드 기반 — 새 종류 증권(예: 새 투자회사 이름)이 생기면 규칙을 보강해야 한다.
- 시안 모드(파일로 열기)의 모의투자는 팀 시안 그대로 브라우저 기록이다 — 서버로 서비스할 때는 쓰이지 않는다.
