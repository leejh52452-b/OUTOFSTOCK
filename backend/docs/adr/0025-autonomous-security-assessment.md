## 맥락
규제 중심 체계(전자금융감독규정 — 수범사항 점검표)는 '했나/안 했나'를 묻는다. 금융당국은 2024년부터 원칙 중심·자율보안·결과책임으로
옮기고 있고(감독규정 293 → 166개 수범사항), 금융보안원은 2026.2 수준진단 프레임워크를 내 '현재(As-is) → 목표(To-be)'를
성숙도로 보게 했다. 특강이 짚은 자율보안의 약점은 **역량 편차·경영진 책임 확대·검증 어려움**이다. 이 서비스는 보안 통제를
많이 갖췄지만(ADR-0011~0024) 스스로 수준을 재는 수단이 없었다 — 근거가 흩어져 있고(문서 20여 개), 위협 모델의 '확인' 열이
가리키는 시험이 실제로 있는지 아무도 보지 않았고, 위험은 가능성·영향 숫자 없이 문장으로만 있었다.

## 결정
1. **수준진단 엔진** — 45개 항목 카탈로그(항목명은 프레임워크 그대로, NIST CSF 2.0 하위 항목 매핑, 목표 등급). 근거 6종
   (문서·구현·자동 시험·운영 점검·자동 대응·실측/훈련 기록)을 **기계가 확인**하고(파일·함수·시험 이름은 구문 트리, 탐지 규칙·
   스케줄 작업은 등록 여부) **근거 종류로 등급을 판정**한다 — 기반 = 문서 + 이행, 발전 = + 자동 시험 + 운영 감시(프로브·자동 대응),
   고도화 = + 자동 대응 + 실측 기록. 운영 모드에서는 프로브 15종을 실제로 돌려 실패한 항목을 기반으로 내린다.
   사람이 정하는 것(근거 연결·목표·범위 상한)은 카탈로그에 이유와 함께 적는다. → '검증 어려움'에 대한 답: 주장마다 기계가 확인하는 근거.
2. **증빙** — 결과는 `security_assessment` 표에 **추가만**(앱 계정은 수정·삭제 권한 없음 — V016), 결과 다이제스트를 감사 체인에
   고정(외부 증인까지). 매월 1일 재진단, 직전보다 내려간 항목·실패한 프로브는 경보. 관리 API `/admin/assessment*`(감사·보안 역할).
3. **진단 → 개선 → 재평가** — 같은 엔진으로 개선 전 기준선을 먼저 재서 저장(`docs/security/assessment/2026-11-02_baseline*.json`),
   가장 약한 분야(공급망 2.0·식별 2.2)부터 개선한 뒤 다시 쟀다. 기준선 카탈로그를 지금 다시 돌려도 같은 등급이 나와야 한다(시험).
4. **자산·위험 등록부** — 자산 5종(데이터 64·업무 동작 26·외부 호스트 25·패키지·구성요소 8)을 코드에서 만들고 C·I·A 점수로 중요도.
   위협 시나리오는 위협 모델 §3(T-01~T-35)을 그대로 읽고, 가능성×영향(고유·잔여)·처리·담당·재검토일을 붙인다. 위험 성향 9 —
   넘으면 계획+기한 또는 승인 수용 필수. '확인' 열의 시험이 실제로 있는지 시험이 검사한다(문서가 거짓말하지 않게).
5. **파일 무결성 감시(4.4)** — 배포 직후 기준선(파일별 SHA-256)을 **소유자 계정만** 기록, 10분마다 비교해 변경·삭제·**새 파일**(웹셸)을
   심각 이벤트·경보. 기준선 행을 DB 에서 고친 흔적(다이제스트 불일치)도 위반.
6. **권한 생명주기(3.2·2.3, 제13조 ①11호)** — 60일 동안 한 번도 켜지 않은 관리 자격 자동 회수(부트스트랩은 비상용 표시), 인사조치
   일괄 회수(자격·활성·대기 요청·세션·계정 중지 한 번에, 한 사람이 즉시). 중지된 계정에는 부트스트랩이 다시 주지 않는다.
7. **사고 대응 모의훈련(5.4·5.3)** — 5개 시나리오(원장 변조·이상 송금 급증·대입 공격·쿠키 탈취·파일 변조)를 격리 DB 에서 자동으로:
   신호 → 탐지 → 자동 차단 → 실제 요청 확인 → 2인 재개. 단계별 경과 시간 기록, 운영 알림 채널로는 보내지 않는다.
8. **공급망(7.1·7.2)** — 제3자 등록부에 선정 기준·이용 요건 S1~S8, 호스트 표가 허용 목록과 한 줄도 어긋나지 않게(시험·프로브).

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 45개 항목을 사람이 등급 매긴 표(문서) | 금방 낡고, 검증할 수 없다 — 특강이 짚은 자율보안의 약점 그대로 |
| 엑셀 점검표(Y/N) | 프레임워크가 버린 방식 — 성숙도와 목표가 없다 |
| 카탈로그 없이 CSF 2.0 106개를 직접 | 국내 금융권은 수준진단 45개 항목으로 진단받는다(신한금융 2026.4 첫 적용) — CSF 는 매핑으로 함께 |
| FIM 을 OS 도구(AIDE·Tripwire)로 | 서버마다 설치·설정이 필요하고, 앱이 결과를 모른다 — 경보·진단과 이어지지 않는다. 앱 안 검사 + 소유자만 쓰는 기준선 |
| 휴면 자격을 경보만 | 경보는 무시된다 — 쓰지 않는 권한은 회수가 기본, 다시 필요하면 2인 승인 |
| 훈련을 운영 DB 에서 | 원장 변조·IP 차단 신호가 실제 서비스를 멈춘다 — 이름·소유·이용자 검사로 격리 DB 에서만 |

## 결과
- 같은 엔진·같은 규칙: 전체 **2.93 → 3.21**(4점 만점), 목표 미달 **9 → 0**개, CSF 2.0 근거 하위 항목 **67 → 76/106**.
  분야별: 공급망 2.0 → 3.0 · 식별 2.2 → 3.0 · 거버넌스 2.57 → 2.86 · 탐지 2.8 → 3.2 · 대응 3.25 → 3.5 · 보호 3.28 → 3.33.
- 위협 35개 모두 점수·처리·담당 · 자동 확인 시험 56건 실재 확인(수동 근거 1건) · 잔여 위험 성향 초과 0.
- 모의훈련 5/5 — 자동 차단까지 23~85ms, 2인 재개 포함 복구 29~422ms(격리 DB, 운영과 같은 비밀번호 해시 강도).

## 한계
- 판정 규칙은 '근거가 있는가'를 본다 — 통제의 강도는 시험·실측 내용과 독립 점검이 판단한다. 금융회사 진단 결과와 직접 비교하지 않는다.
- 범위는 서비스 1개 — 경영진·예산·교육(1.2·1.5·1.7)은 상한·제외로 적었다.
- FIM 은 10분 주기 — 그 사이의 변경은 다음 검사까지 모른다. 서버 root 와 DB 소유자 권한을 함께 가진 공격자는 기준선도 바꿀 수 있다
  (그 기록은 감사 체인·외부 증인에 남는다). 코드 디렉터리 읽기 전용(systemd)·읽기 전용 컨테이너가 1차 방어.
- 훈련은 신호 주입형 — 탐지 로직(원장 재계산·FDS·서명 검증·해시)은 각 단위 시험이 검증한다. 시간은 자동화 구간이다.
