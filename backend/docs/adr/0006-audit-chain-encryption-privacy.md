# ADR-0006 감사 로그는 해시 체인으로, 민감 값은 AES-256-GCM 으로, 개인정보는 '처음부터 덜 남기기'로

| 상태 | 채택 · 2026-10-10 |
| 범위 | 3번 정보보호 — 기록의 무결성·저장 데이터 보호·개인정보 최소화·화면 보안 헤더 |

## 맥락
송금·결제·커뮤니티 관리 같은 행위는 **나중에 증명**할 수 있어야 하고(누가 언제 무엇을), 그 기록은 관리자도 몰래 고칠 수 없어야 한다.
DB 에는 KIS 접근토큰·결제 키처럼 유출되면 바로 쓰이는 값이 있었다(평문). 접속 기록의 IP·커뮤니티 작성자 아이디(이메일형일 수 있음)는
필요 이상으로 남거나 공개됐다. 금융권 기준(전자금융감독규정의 접속·처리 기록 보존, 개인정보 보호법의 최소 수집·가명 처리 취지)을 참고했다.

## 결정
1. **감사 로그 해시 체인**(`audit_log`): 각 행 = 직전 행 해시(prev_hash) + 자기 내용의 SHA-256(row_hash).
   중간 행을 고치거나 지우면 그 뒤가 전부 어긋나 `verify()` 가 **처음 깨진 행 번호**를 돌려준다.
   - 쓰기는 advisory lock 으로 한 번에 하나(체인 분기 방지). 앱 계정은 INSERT·SELECT 만(UPDATE·DELETE 권한 없음, ADR-0005).
   - 보관 기간(`AUDIT_RETENTION_DAYS`, 기본 730일)이 지나 지울 때는 남은 첫 행의 앞 해시를 시작점(anchor)으로 기록해 검증을 이어 간다.
   - 기록 대상: 가입·로그인·로그아웃·비밀번호 변경·탈퇴, 송금, 결제 승인, 커뮤니티 글·댓글·삭제·신고·관리 조치, 관리자의 감사 로그 열람.
2. **민감 값 암호화 저장**: AES-256-GCM(인증 암호화), 형식 `enc:v1:<키ID>:<base64(nonce|암호문|태그)>`.
   - **AAD 에 '어느 표·열의 값인지'** 를 넣는다 — 암호문을 다른 행·열로 옮겨 붙이면 복호화 실패.
   - 키 교체: 새 키는 `DATA_ENCRYPTION_KEY`, 예전 키는 `DATA_ENCRYPTION_KEYS_OLD`(읽기 전용), 키ID 로 구분.
   - 비밀번호는 암호화가 아니라 되돌릴 수 없는 해시(PBKDF2 600,000회)로만.
3. **개인정보 최소화**
   - 접속·감사 기록의 IP 는 원문 대신 HMAC 가명(같은 IP 인지 비교만 가능, 되돌릴 수 없음).
   - 커뮤니티: 전화번호·이메일·주민등록번호 형태가 있으면 **저장 자체를 거부**, 공개 화면의 작성자는
     `앞 2글자***#HMAC 4자리`(같은 사람 글은 구분되지만 아이디는 복원 불가), 실명 아이디는 관리자 검토 큐에서만.
   - 외부 채팅방·리딩방 유도는 '검토 대기'(공개 전 관리자 확인), 과장·확정 수익 표현은 '투자 유의' 표시 — 유사투자자문·불공정거래 대응.
4. **화면 보안 헤더**: 기본 CSP(`script-src 'self'` + 결제 위젯 도메인, `object-src 'none'`, `frame-ancestors 'self'`),
   nosniff·클릭재킹 방지·리퍼러 최소화. 본문은 항상 글자로 저장하고 화면에서 이스케이프(XSS).
5. **공급망 점검**: `tools/security_scan.sh` = pip-audit(알려진 취약점) + bandit(정적 분석) + 숨은 방향 제어 문자(Trojan Source) — CI 에서 매번.

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 감사 로그를 일반 로그 파일로 | 파일 수정·삭제를 탐지할 수 없다 |
| 외부 WORM 저장소·블록체인 | 학생 VM 규모에 과함. 해시 체인 + DB 권한 분리로 '몰래 고치기'를 탐지 가능하게 하는 것이 목표 |
| DB 전체 암호화(TDE)만 | 디스크 도난엔 효과적이지만 DB 덤프·SQL 인젝션 유출엔 무력 — 열 단위 암호화가 필요 |
| 작성자 아이디 그대로 공개 | 이메일형 아이디가 그대로 노출 — 최소 공개 원칙 위반 |

## 결과
- 감사 행 1개를 DB 에서 직접 고치면 검증이 그 행 번호를 짚는다(테스트). 화면: 종목 토론 → 관리 → '해시 체인 검증'.
- 감수한 점: 키를 잃으면 암호화된 토큰·결제 키는 복구 불가(토큰은 재발급, 결제 키는 재조회로 대응) — 키는 .env 밖 별도 보관 권장.
  감사 로그 쓰기가 직렬화돼 초당 수천 건 규모에는 맞지 않는다(현재 규모에선 충분).
