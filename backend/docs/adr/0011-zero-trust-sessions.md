# ADR-0011 세션은 '짧은 접근 토큰 + 회전하는 갱신 토큰 + HttpOnly 쿠키'로, 매 요청 다시 확인한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-20 |
| 범위 | 제로트러스트 — 식별자·신원 |
| 코드 | `app/security/sessions.py` · `pep.py`(쿠키·CSRF) · `device.py` · `totp.py` · 화면 `api()`·`refreshSession()` |
| 시험 | `tests/test_zero_trust.py`(만료·회전·재사용·기기·유휴/절대 만료·잠금·TOTP) · E2E ③⑤⑧ |

## 맥락
이전 로그인은 24시간 토큰 하나를 `localStorage` 에 두었다. 갱신·회전이 없어 한 번 새면 하루 동안 쓸 수 있고, XSS 한 번이면
스크립트가 토큰을 읽어 갈 수 있으며, 서버는 '지금 이 요청이 정상 세션인지'를 토큰 서명 외에는 보지 않았다.

## 결정
| 장치 | 값 | 이유 |
|---|---|---|
| 세션 1개 = 로그인 1회 | DB `auth_session`(기기 지문·IP 대역·인증 강도·마지막 사용) | 폐기·목록·동시 수 제한의 기준 |
| 접근 토큰 `oosa_…` | **10분**, DB 엔 SHA-256 만 | 새도 10분 · 세션 폐기 즉시 무효 |
| 갱신 토큰 `oosr_…` | 쓸 때마다 새 토큰(회전), 쓴 토큰 재사용 → **사용자 전체 세션 폐기** + critical 이벤트 | OAuth 2.0 Security BCP 의 재사용 탐지. 탭 둘의 동시 갱신은 30초 유예로 구분 |
| 유휴·절대 만료 | 30분 · 12시간 | 안전성 확보조치 기준 제6조④(미사용 시 자동 차단) |
| 기기 결속 | 브라우저·OS 계열이 바뀌면 세션 폐기, IP 대역 변경은 위험 신호 | 버전은 빼서 자동 업데이트로 끊기지 않게 |
| 전달 방식 | 웹: HttpOnly·SameSite=Strict 쿠키(HTTPS 면 `__Host-`), 갱신 쿠키는 `Path=/auth` 만 · 앱: Bearer | 스크립트가 토큰을 못 읽는다 |
| CSRF | 쿠키 인증 변경 요청은 이중 제출 토큰 + Origin | 쿠키를 쓰는 대가 |
| 동시 세션 | 5개(넘으면 가장 오래된 것 종료) · 목록·개별 폐기·전체 로그아웃 | 분실 기기 대응 |
| 2단계 | TOTP(재사용 차단·±30초) + 복구 코드, 비밀은 봉투 암호화(AAD = 계정) | 관리 역할 활성에는 필수 |

화면은 `401 token_expired` 를 받으면 `/auth/refresh` 를 한 번만(동시 요청은 하나로 묶음) 부르고 원래 요청을 다시 보낸다.

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 서명 JWT(무상태) | 폐기가 안 된다 — 탈퇴·비밀번호 변경·탈취 탐지 후에도 만료까지 유효. 결국 폐기 목록(=상태)이 필요 |
| 토큰 수명만 줄이기(갱신 없음) | 10분마다 다시 로그인 — 사용성 붕괴 |
| Redis 세션 저장소 | 새 인프라 하나 추가. PostgreSQL 로 충분(부하 시험 4 workers 185 RPS, 세션 확인 포함) |

## 개정(2026-10-23, 독립 점검)
- **로그인은 추가 인증으로 치지 않는다** — '최근 5분 안 재확인'을 로그인 시각 또는 추가 인증 시각으로 판정하던 것을 추가 인증 시각만으로.
  예전엔 피해자가 로그인한 직후 5분 동안 탈취된 세션이 다른 IP 대역(위험 신호)에서도 탈퇴·고액 송금·FDS '추가 인증' 등급을 재확인 없이
  통과했다. 금융권 관행(이체·해지마다 추가 인증)과도 맞춘다. 비용: 로그인 직후의 탈퇴·고액 송금도 비밀번호를 한 번 더 묻는다.
  시험 `test_stolen_session_right_after_login_cannot_skip_step_up` · E2E ⑥⑨(방금 로그인한 세션에서도 창).

## 결과
- 로그인 화면 p95 가 비로그인보다 약 35ms 높다(세션 확인 DB 조회 1회 + RLS 문맥) — 보안 비용으로 감수(부하 시험 보고서).
- 쿠키 전환으로 CSRF·`/csp-report` 같은 '헤더를 못 붙이는 요청' 처리가 필요해졌다(정책 `csrf: false` 는 상태를 안 바꾸는 보고뿐).
