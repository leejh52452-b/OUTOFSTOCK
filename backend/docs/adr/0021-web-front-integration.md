# ADR-0021 팀 확정 화면(다섯 장)을 그대로 서빙하고 서버와 잇는다 — 공용 런타임 · 같은 출처 · 신뢰 경계

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-27 (ADR-0018 을 여러 화면으로 확장 — 예전 한 장짜리 화면 `app/static/index.html` 대체) |
| 범위 | 애플리케이션(화면 서빙·XSS 방어·세션) · 데이터(웹 활동 표 2개) |
| 코드 | `web/`(index·learn·news·practice·mypage + `assets/oos/runtime.js`) · `app/webui.py`(허용 목록·nonce·CSP·자산 캐시) · `app/api.py`(`/`·`/{page}.html`·`/app`→`/`·`/learn/quiz`·`/practice/records`) · `app/services/quiz.py`·`practice_records.py` · `sql/migrations/V014__web_activity_rls.sql` |
| 시험 | `test_web_security.py`(화면별 nonce·CSP·data-on 등록 함수·외부 스크립트 0·로그인 유지) · `test_web_front.py`(화면↔서버 계약) · `test_quiz.py` · `test_practice_records.py` · `test_accessibility.py` · `tools/e2e_web.py`(34항목 + axe) |

## 맥락
팀이 화면 다섯 장(GitHub `OUTOFSTOCK`)의 겉모습을 확정했다. 화면은 예시 데이터·`localStorage`·`alert('디자인 시안이에요')` 로만
움직였고, 인라인 이벤트 핸들러 33곳·`innerHTML` 템플릿이 많다. 우리 서버의 보안 기준(쿠키 세션·CSRF·nonce CSP·Trusted Types·
추가 인증·RLS)을 그대로 지키면서, **겉모습은 바꾸지 않고** 실제 계정 데이터로 움직이게 해야 한다. 팀은 계속 같은 파일을 고친다.

## 결정
1. **같은 출처 서빙(교차 출처 없음)** — 서버가 `web/` 을 그대로 내보낸다. `/`·`/learn.html`… 는 **허용 목록**(경로 조각을 파일 이름으로
   쓰지 않음). 요청마다 새 nonce 를 **인라인 스크립트에만** 붙이고(파일 스크립트는 `'self'` 로만 — 누가 외부 `<script src>` 를 넣어도
   브라우저가 막고 보고), CSP 는 `connect-src 'self'`·`frame-src 'none'`·`form-action 'self'`·`trusted-types default`·`script-src-attr 'none'`.
   쿠키 세션·CSRF 를 그대로 쓰므로 CORS 를 열 필요가 없다. 옛 주소 `/app` 은 `/` 로 308.
   그림은 하루 캐시, 스크립트는 매번 확인 — 확인 기준은 **내용 ETag**(SHA-256)이고 Last-Modified 는 보내지 않는다. 설치본(tar)은
   재현 가능하게 파일 시각을 모두 0 으로 풀어서, 기본(시각·크기) ETag 로는 글자 수가 같은 수정(색 코드·숫자)을 브라우저가 304 로 놓친다.
2. **공용 런타임 하나(`assets/oos/runtime.js`, 모든 화면이 가장 먼저 로드)** — ① 신뢰 타입 기본 정책 ② `data-on`/`data-on-submit`/
   `data-on-self` 해석기(eval 없음) — **화면이 `OOS.actions({...})` 로 등록한 함수만** 호출(전역 이름 조회 없음) ③ `OOS.api()`:
   CSRF·토큰 갱신(동시 만료에도 1번)·추가 인증 창·2단계 인증·늦은 응답 버리기 ④ 로그인 힌트·헤더·SSE·탭 간 동기화.
   팀 코드는 제자리에 두고 `[백엔드 연동]` 주석으로 바꾼 곳만 표시 — 팀이 계속 고칠 수 있게.
   팀 저장소 → 서버 반영은 `tools/sync_web.py`(화면·assets·images 만, 연동판이 아닌 옛 시안은 거부, 규칙 위반 미리 경고) →
   위 시험이 계약(설문 문항·용어·퀴즈 해시·등록 함수)을 다시 확인.
3. **데이터 원칙** — 로그인하면 서버가 원본(브라우저에 쓰지 않음, 공용 PC), 로그인 전에는 브라우저에만 두고 **로그인하면 계정으로 옮긴 뒤 지움**
   (학습 표시·오늘 퀴즈). 로그아웃하면 브라우저 사본을 지운다. 우리 서버 없이 열면(파일·Live Server·GitHub Pages — 디자인 작업)
   서버 기능만 빠지고 시안 예시 그대로 — 서버가 내보낼 때만 `<head>` 에 표식(`<meta name="oos-server">`)을 붙여 구분한다
   (주소가 http 인지로 가르면 Live Server 에서 없는 API 를 부르며 화면이 비어 버린다).
4. **신뢰 경계를 데이터마다 정한다**
   | 데이터 | 누가 계산 | 서버가 하는 일 |
   |---|---|---|
   | 투자 성향 | 서버 | 화면은 '문항 번호·보기 번호'만 — 서버 채점·이력(같은 문항 은행인지 시험이 확인) |
   | 퀴즈 점수 | **서버가 다시 만든다** | 화면과 같은 문제은행·같은 날짜 공식(FNV-1a + mulberry32, JS 32비트 연산 그대로)을 파이썬으로 — 답만 받아 채점, 하루 1행, 날짜는 ±1일 |
   | 퀴즈 보상(10-31) | 서버(점수 × 단가) | 기록과 **같은 트랜잭션**에서 지갑·원장·분개(상대 계정 판촉비). **한국 날짜 하루 1번**을 (계정, 보상 날짜) 부분 유일 인덱스가 보장 — ±1일 날짜를 섞거나 두 탭이 동시에 내도 1번. 정답 키가 화면에도 있어 상한(5 × 단가)까지는 누구나 받을 수 있음 — 교육용 가상머니라 감수 |
   | 실습 수익률 | 브라우저(차트를 화면이 가짐) | 다시 셀 수 없다 → **범위·종류만 확인**(기법 4·방식 2·−100%~+1000%) + 시간당 상한, **가상머니와 잇지 않는다**(조작해도 얻는 것 없음) |
   | 출석·송금·탈퇴 | 서버 | 기존 그대로(멱등키·추가 인증·FDS·원장) |
5. **'로그인 유지'** — 체크하지 않으면(기본) 세션 쿠키(브라우저를 닫으면 끝 — 공용 PC), 체크하면 12시간 수명. 세션 행에 저장해 갱신해도 유지.
   서버 만료 규칙(유휴 30분·절대 12시간)은 같다.

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 팀 화면을 정적 호스팅(GitHub Pages) + CORS | 쿠키 세션을 교차 출처로 보내야 함(SameSite=None) — CSRF 면이 넓어진다. 같은 출처면 SameSite=Strict 그대로 |
| 화면 코드를 프레임워크(React)로 옮기기 | 팀이 고치는 파일과 갈라진다 — 겉모습 합의를 깨기 쉽다 |
| 화면마다 따로 인라인 해석기 | 보안 코드가 다섯 벌로 갈라져 한 곳만 고치게 된다 — 공용 런타임 하나 |
| 퀴즈 점수를 화면이 보냄 | 숫자 하나만 바꾸면 만점 — 답을 받아 서버가 채점(정답 키는 화면에도 있지만 '기록의 무결성'은 서버가 지킨다) |
| 실습 결과를 서버가 재연 | 예시 차트는 브라우저 난수(가우스·로그)로 그려 JS/파이썬 부동소수 결과가 같다는 보장이 없다 — 대신 보상과 분리 |

## 결과
- 인라인 핸들러 33 → 0, 화면 다섯 장 콘솔 오류 0 · CSP 위반 0, axe(WCAG 2.1 AA) 위반 0(다섯 화면 + 추가 인증 창).
- 겉모습 변화는 접근성 두 가지뿐: `--text-muted` #94a3b8 → #64748b(대비 2.56 → 4.76:1), 학습 화면 '주의' 배지 주황 한 단계·숫자 투명도 제거.
- 시안에 없던 상태(송금 입력·채팅 대화·관심 종목 검색 결과·설문 전 성향)는 같은 클래스·색으로 최소한만 그렸다.
- 웹 활동 표 2개(practice_record·quiz_attempt): FORCE RLS·데이터 분류 L3·탈퇴 시 삭제·계보 문서 반영.
