# ADR-0022 양봉이 꾸미기 — 화면 파일이 카탈로그 · 서버 가격으로 차감 · 산 기록과 차감을 한 트랜잭션

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-31 (팀 결정 — 가상머니로 마스코트 '양봉이'를 꾸민다) |
| 범위 | 애플리케이션(새 화면·아이템 그림) · 데이터(옷장 표 1개 · 원장 사유 1개) · 정책(동작 1개) |
| 코드 | `web/avatar.html` · `web/assets/avatar-items.js`(그림·이름·가격) · `tools/build_avatar_items.py` → `app/data/avatar_items.json` · `app/services/avatar.py` · `app/api.py`(`/avatar/catalog·me·buy·equip`) · `sql/migrations/V015__avatar_rls.sql` · 마이페이지 프로필·홈 로그인 카드 그림 |
| 시험 | `test_avatar.py`(카탈로그 해시·6부위×5등급·10배 가격 · 한 트랜잭션 차감·분개 · 두 번 눌러도 1번 · 잔액 부족 · 화면 가격 불일치 409 · 착용 규칙·DB 부분 유일 인덱스 · 계정 격리 · 위험 신호 추가 인증 · 탈퇴 삭제) · `test_web_security.py`(새 화면 nonce·CSP·data-on) · `test_accessibility.py` · `tools/e2e_web.py`(화면에서 사기 → 서버 가격 차감 · axe) |

## 맥락
10-20 회의에서 기각된 예전 '아바타'(표 `avatar`·`avatar_owned`, V009 로 파기)와 달리, 이번에는 팀 마스코트 양봉이를
**모자·옷·바지·신발·안경·펫** 6부위로 꾸민다. 부위마다 5개, 가격 차이가 커서 '빈부격차'가 보이게(팀 요청).
가상머니가 실제로 빠지는 기능이라 송금과 같은 수준으로 지켜야 한다 — 가격 위조, 두 번 결제, 돈 없이 아이템만 받기, 남의 옷장.

## 결정
1. **카탈로그 = 화면 파일 하나** — 그림(SVG 코드)·이름·가격을 `web/assets/avatar-items.js` 에만 적는다.
   서버 사본은 `tools/build_avatar_items.py` 가 node 로 그 파일을 평가해 id·부위·등급·이름·가격만 꺼내 만든다(원본 SHA-256 기록).
   시험이 해시를 비교한다 — 팀이 가격을 고치고 도구를 잊으면 CI 가 막는다(퀴즈 문제은행과 같은 방식, ADR-0021).
2. **가격은 서버가 정한다** — 화면은 아이템 id 만 보내고 차감은 서버 사본의 가격. 화면이 사용자에게 보여 준 가격(`price`)도 같이 보내
   **서버 가격과 다르면 409 로 아무것도 바꾸지 않는다**(캐시에 남은 옛 화면이 1만원이라 보여 주고 1억을 빼는 일이 없게 — 사용자가 동의한 금액
   = 실제 빠지는 금액일 때만 결제).
3. **산 기록 + 지갑 차감 + 착용 = 한 트랜잭션** — `avatar_closet` 에 (계정, 아이템) PK 로 `INSERT … ON CONFLICT DO NOTHING`(이미 가졌으면 400,
   돈을 다시 받지 않음) → `wallet.debit`(멱등키 `avatar:<계정>:<아이템>`, 잔액 부족이면 예외 → 기록도 취소) → 바로 입기.
   원장 사유 `avatar_buy`, 분개 상대 계정 `sys:avatar_shop`(가상머니가 사라지는 곳 — 시산표 0 유지). 같은 계정의 꾸미기 요청은
   계정별 advisory lock 으로 줄을 세운다(두 탭에서 동시에 사도 1번, 동시에 갈아입어도 유일 조건 충돌 없이).
4. **부위당 하나만 입는다 — DB 가 보장** — `(username, slot) WHERE equipped` 부분 유일 인덱스. 갈아입기 요청은 바꿀 부위만 보내고
   (`{"hat": "hat-3", "pet": null}`) 한 트랜잭션 — 하나라도 틀리면(안 산 아이템·다른 부위·없는 부위) 전부 그대로.
5. **몸값·수저는 저장하지 않고 계산** — 입은 아이템 가격 합(몸값) → 흙수저(0)·동수저(30만)·은수저(300만)·금수저(3,000만)·다이아수저(3억).
   등급 가격(서민 1만·보통 10만·고급 100만·명품 1,000만·전설 1억)의 3배씩이라 '그 등급을 세 부위쯤 입어야' 다음 수저. 저장한 값은 가격이
   바뀌면 어긋난다 — 매번 카탈로그로 계산.
6. **정책·데이터 보호는 기존 틀 그대로** — 구매는 새 정책 동작 `avatar.buy`(사용자, **위험 신호가 있으면 추가 인증** — 큰돈이 빠질 수 있다),
   착용은 `account.write`, 조회는 `account.read`. 옷장은 데이터 분류 L3 · FORCE RLS(V015) · 탈퇴 시 즉시 삭제 · 계보 문서 반영.
   표 이름이 `avatar_owned` 가 아닌 까닭: V009 가 그 이름을 지우는 마이그레이션이라 새로 설치하는 DB 에서 사라진다.
7. **그림은 코드(SVG)** — 몸통·얼굴·불꽃과 같은 좌표계(420×440)에 부위별 층으로 겹친다. 30개 조합이 따로 그림 없이 맞물리고, 모자를 쓰면
   불꽃이 모자 위로 올라간다(아이템의 `lift`). 파일 30개 대신 한 파일(약 40KB), 화면 CSP 안에서 그대로(인라인 SVG · 프로필은 `data:` 그림).
8. **되팔기·선물은 없다** — 멱등키가 '한 번 산 아이템'을 전제로 한다. 만들게 되면 키(`avatar:<계정>:<아이템>:<회차>`)부터 바꾼다.

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 카탈로그를 DB 표로(관리 화면에서 수정) | 그림은 화면 파일에 있어야 한다 — 두 곳이 갈라진다. 파일 하나 + 해시 시험이면 한쪽만 고치는 실수를 CI 가 잡는다 |
| 화면이 가격을 보내고 서버가 그 값으로 차감 | 요청 하나만 고치면 1억짜리를 1원에 산다 — 가격은 확인용으로만 받는다 |
| 착용 상태를 사용자 표의 JSON 열로 | '산 것만 입는다'·'부위당 하나'를 DB 가 보장할 수 없다 — 행 + 부분 유일 인덱스 |
| 몸값·수저를 열로 저장 | 가격·등급 기준을 바꾸면 옛 값이 남는다 — 계산 비용은 아이템 6개 합 |
| 아이템마다 PNG | 30장 × 해상도별 — 마스코트 화풍을 맞추기 어렵고 조합 위치를 따로 맞춰야 한다. SVG 층이면 같은 좌표계 |

## 결과
- 30개(6부위 × 5등급), 무대 배경이 수저마다 바뀜(흙바닥 → 동 → 은 → 금빛 후광 → 다이아 반짝이) · 사기 전 입어 보기(저장 안 함) ·
  입어 본 옷 한 번에 사기 · 잔액 부족 표시 · 마이페이지 프로필·홈 로그인 카드가 꾸민 모습(수저 배경) · 모든 화면 메뉴에 '양봉이 꾸미기'.
- 정책 동작 22 → 23(버전 2026-10-31.1), 경로 121 → 125, FORCE RLS 표 17 → 18.
- 접근성: 새 화면 axe 위반 0(데스크톱·모바일 390px). 이 과정에서 기존 화면들의 모바일 문제 두 가지도 고쳤다 — 접힌 메뉴의 글자를
  `display:none` 대신 화면에서만 숨김(아이콘 링크에 이름), 좁은 화면 헤더 '마이페이지' 링크에 이름(런타임). 겉모습 변화 없음.
