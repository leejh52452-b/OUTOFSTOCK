# ADR-0009 테마는 '사람이 고른 목록' 대신 공식 자료의 근거를 점수로 합쳐 정하고, 근거·시점·검증을 함께 남긴다

| 항목 | 내용 |
|---|---|
| 상태 | **폐기** · 2026-10-20 — 시장 분석 화면이 팀 회의에서 기각되어 테마 분류·저장 구조를 걷어 냄(`sql/migrations/V009__retire_features.sql`). 설계 기록으로만 남긴다(코드·표 없음). 채택 · 2026-10-10 |
| 범위 | 네이버 증권식 '테마별 종목 묶음과 등락률' (산업·골라보기 › 테마, 종목 상세 테마 칩, 데이터 분석 › 테마 분류 검증) |
| 코드 | `app/data/themes.json`(사전) · `sql/migrations/V008__themes.sql` · `app/collectors/theme_sources.py` · `app/services/theme_platform.py` · `app/models/theme_quality.py` |
| 명령 | `run.py theme-build` · `theme-probe` · `theme-eval [--synthetic]` · `theme-label-export/import` (매일 배치 `run.py real` 의 '테마 분류' 단계) |

## 맥락
네이버 테마 목록은 사람이 관리하는 분류라 공식 API 가 없고, 화면을 긁어 오면 약관 문제가 된다. 그렇다고 손으로 목록을 만들면
몇 개 종목에서 멈추고(예전 `THEME_MAP` 5개 테마 × 2~3종목), 왜 그 종목이 들어갔는지 설명할 수 없고, 시간이 지나면 낡는다.
테마는 업종(KSIC)과 다르다 — 'AI'·'원전'·'밸류업'은 업종을 가로지른다.

## 결정
1. **근거를 공식 자료에서 모은다**(원천마다 따로 실패해도 나머지로 분류):
   - 테마형 ETF 구성종목 — KRX 'ETF 일별매매정보'로 ETF 이름·기초지수를 받아 사전의 ETF 키워드로 테마형 ETF 를 고르고
     (레버리지·인버스·선물·해외·채권 제외), 한국투자증권 'ETF 구성종목시세'(FHKST121600C0)로 구성종목·비중을 날짜별 스냅샷.
     같은 기초지수를 따르는 ETF 는 순자산이 가장 큰 하나만 받는다(구성이 같으니 근거를 두 번 세지 않게, 호출 절약).
   - 사업보고서 'II. 사업의 내용' — OpenDART 공시서류원본파일(zip)에서 그 구간만 정규식으로 뽑아 4만 자 저장(재분류 때 다시 받지 않음).
   - 업종코드(KSIC 10차, DART 기업개황) 접두어 · 뉴스 제목(최근 30일, **보조** — 이것만으로는 소속 불가).
2. **점수 규칙**(사전 `rules`, 테마별로 덮어쓰기): ETF 단일 테마 0.25 · 여러 테마 이름 ETF 0.15 · 비중 3%↑ +0.1(최대 0.6) /
   사업보고서 강(키워드 2종·4회·1만 자당 1회↑) 0.45 · 약(2회↑) 0.25 / 업종코드 0.45 / 뉴스 0.1.
   **소속 = 합 ≥ 0.45 이고 구조적 근거(ETF·사업보고서·업종코드) 하나 이상.** 흔한 말(AI·플랫폼)은 공시 기준을 높이고,
   '자동차보험'처럼 다른 뜻으로 세어지는 말은 `exclude` 로 먼저 지운다. 영문 약어는 단어 경계로만 센다(MAIN ≠ AI).
3. **시점(PIT)**: 근거마다 `known_at`(공시일 · 지금 점수를 이루는 ETF 가운데 가장 늦게 담은 날 · 업종코드를 처음 받은 날).
   소속 시작일 = 그날까지 알려진 근거만으로 기준을 넘은 가장 이른 날. 소속은 이력형(SCD2) — 빠지면 그날로 닫고
   (`valid_to` 는 그날 비소속), 다시 들어오면 새 행(빠져 있던 기간과 겹치지 않게). `members_at(테마, 날짜)` 로 그때의 소속을 재현.
4. **성과**: `analytics.theme_performance(기간)` — 단순평균(네이버 방식) · 기간 초 시총 가중 · 중앙값, 상승/하락, 주도주(기간 1위),
   대표 종목(시총 1위), 투자 유의 수. **단순평균 − 시총가중 차이**를 보여 준다(크면 소형주가 테마를 끄는 중 — 과열 신호).
   테마 지수는 현재 구성 종목의 동일가중·매일 재조정·수정주가(ADR-0010) 로그수익률 — '현재 구성으로 과거를 다시 계산'이라는
   사후 선택 편향을 화면에 적는다.
5. **검증을 기능의 일부로**(`theme-eval`, 결과는 `analytics.model_run`):
   정밀도(사람 라벨, 95% 윌슨 구간 — 표본이 작아서) · 근거별 정밀도(어떤 근거를 믿을 만한가) ·
   원천 간 일치(ETF 편입 중 사업보고서·업종코드도 같은 테마인 비율 — 서로 독립인 근거) ·
   **응집도**(시장 초과 일수익률의 평균 쌍별 상관을, 테마 종목마다 같은 시가총액 5분위에서 뽑은 무작위 바구니 200개와 비교한 z) ·
   **새 테마 후보**(거래대금 상위 500종목 초과수익 상관의 평균 연결 군집 중 기존 테마와 안 겹치는 촘촘한 묶음).

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 네이버 테마 화면 수집 | 약관·저작권 문제, 출처의 분류 근거를 설명할 수 없음 |
| 손으로 만든 목록(예전 `THEME_MAP`) | 확장 불가 · 근거 없음 · 낡음 |
| 뉴스 동시 언급만으로 분류 | 기사 한두 건에 흔들리고 '이야기만 있는 테마'가 섞임 — 보조 근거(0.1)로만 |
| 가격 상관 군집만으로 분류 | 이름이 없고, 같이 움직이는 이유(업종·대형주 효과)가 섞임 — '새 테마 후보'를 사람에게 제안하는 데만 |
| 임베딩·언어모델 분류 | 근거 문장을 보여 주기 어렵고 재현·검증 비용이 큼 — 키워드 규칙 + 근거 문장 + 라벨 정밀도로 충분히 설명 가능한 쪽을 택함 |

## 결과
- **방법 확인**(`theme-eval --synthetic`, 가짜 시장 300종목 × 120일에 공통 요인 묶음 5개를 심음):
  심은 묶음 응집도 z **24.1~31.3**, 무작위 묶음 z **−1.3~1.7**. 가격 군집이 심은 묶음 **5/5** 를 되찾음(4개 완전, 1개 10/12), 잡음 묶음 0.
- 빈 날(신규 상장·정지)을 0 으로 채운 채 T 로 나누면 상관이 작아져 응집도가 낮게 나온다 → 두 종목이 함께 있는 날 수로 나눈다
  (20% 빈 날에서 예전 방식은 0.1 넘게 작음, 고친 방식은 완전한 자료와 0.06 이내 — 테스트로 고정).
- 실데이터 정밀도·응집도는 VM 에서 `theme-build → theme-label-export(라벨) → theme-eval` 후 `tools/model_report.py` 가
  `docs/models/model_results.md` 에 채운다(라벨 없이 숫자를 지어내지 않는다).
- 감수한 점: 키워드 규칙은 문맥을 모른다(고객 산업을 말한 문장도 센다 — 공급망 포함으로 해석) · ETF 이름 매핑은 사전 품질에 달림 ·
  KRX 'ETF 일별매매정보'는 별도 이용신청이 필요(없으면 ETF 근거 없이 사업보고서·업종코드로만 분류).

