# ADR-0003 시세 이력 = 연도 RANGE 파티션 + (측정 후) 날짜 B-tree, 화면 입력 = 머티리얼라이즈드 뷰 스냅샷

| 항목 | 내용 |
|---|---|
| 상태 | 채택 · 2026-10-10 |
| 범위 | 2번 데이터 플랫폼 — 인덱스 설계와 EXPLAIN 전후 비교 |
| 코드 | `sql/migrations/V001`(파티션 표) · `V003`(스냅샷 MV·업종 함수) · `V004`(날짜 인덱스) · `tools/bench_explain.py` |
| 문서 | `docs/perf/explain_report.md`(실측 표·실행 계획) · 화면: 데이터 분석 → 데이터 현황 |

## 맥락
`analytics.price_history` 는 전 종목 × 10년 ≈ 700만 행(약 0.9GB)이 된다. 화면이 실제로 던지는 질문은 대부분
**"가장 최근 날"** 또는 **"최근 1년"** 이다(최신 거래일, 그날 거래대금 순위, 거래량 급증, 52주 신고가, 골라보기).
인덱스를 '감'으로 붙이지 않고, 같은 데이터·같은 쿼리로 구성별 실행 계획과 시간을 재서 고르기로 했다.

## 실측(합성 2,700종목 × 10년 = 7,041,600행, PostgreSQL 16, 3회 중앙값)
| 쿼리 | A 파티션 없음 | B 연도 파티션 | **C B + trade_date B-tree** | D B + BRIN |
|---|---|---|---|---|
| Q1 최신 거래일 `max(trade_date)` | 504ms | 819ms | **0.03ms** | 777ms |
| Q2 그날 거래대금 상위 50 | 208ms | 33ms | **0.71ms** | 0.72ms |
| Q3 한 종목 1년 | 0.32ms | 0.38ms | 0.40ms | 0.36ms |
| Q4 거래량 급증(윈도 함수) | 331ms | 156ms | **106ms** | 109ms |
| Q5 52주 신고가 | 275ms | 155ms | 149ms | 148ms |
| Q6 월별 거래대금 3년 | 501ms | 478ms | 466ms | 460ms |

읽은 것: ① 파티션만으로는 **Q1 이 오히려 느려진다**(11개 파티션을 모두 훑음) — 파티션 제외는 날짜 조건이 있을 때만 효과.
② B-tree 는 파티션마다 `max` 를 인덱스 끝에서 바로 읽어(Index Only Scan) 0.03ms. ③ BRIN(264kB)은 B-tree(48MB)보다
180배 작고 범위 조회(Q2·Q4)는 거의 같지만 **`max` 에는 못 쓴다**. ④ Q3(종목별)은 기본키 `(ticker, trade_date)` 로 이미 충분.

## 결정
1. **연도 단위 RANGE 파티션**(`price_history_2016 …`): 최근 1년 쿼리는 파티션 1~2개만 읽고, 오래된 해는 `DETACH` 로 통째 보관·삭제.
   새 연도 파티션은 적재기가 필요할 때 만든다(앱 계정은 소유자 권한 함수로 — ADR-0005).
2. **기본키 `(ticker, trade_date)` + 부모 표에 `trade_date` B-tree**(V004) — 모든 파티션(앞으로 생길 것 포함)에 같은 인덱스.
   BRIN 보다 크지만 '최신일'이 모든 화면의 출발점이라 B-tree 를 택했다.
3. **실행 시점 파티션 제외**: 최신일을 CTE 조인이 아니라 **스칼라 서브쿼리**(`(SELECT d FROM last)`)로 넘긴다 —
   CTE 를 조인하면 계획 시점에 값을 몰라 전 파티션을 훑는다.
4. **머티리얼라이즈드 뷰 `mv_stock_snapshot`**: 종목마다 1일·1주·1개월·3개월·1년 등락률과 거래대금, 52주 고가·신고가 여부,
   연속 상승일, 거래량 배수, 재무 비율, 투자 유의 여부를 적재가 끝날 때 한 번 계산한다
   (`REFRESH … CONCURRENTLY` — 읽기를 막지 않음, 그래서 `ticker` 유일 인덱스를 둔다).
   골라보기·업종·경보 화면은 이 결과만 읽는다(요청당 수 ms).

## 검토한 대안
| 대안 | 버린 이유 |
|---|---|
| 월 단위 파티션 | 파티션 120개 — 계획 비용·관리 대상만 늘고, 연 단위로도 '최근 1년'은 2개 이하 |
| 종목 해시 파티션 | 화면 질문이 '날짜' 중심이라 제외 효과가 없다 |
| 매 요청 실시간 집계 | 골라보기 한 번에 수백 ms~초 — 동시 요청에 약하다 |
| BRIN 단독 | Q1(최신일) 777ms — 측정으로 기각 |

## 결과
- 최신일 504ms → 0.03ms, 그날 순위 208ms → 0.7ms, 골라보기·업종 화면은 스냅샷 덕에 요청당 수 ms.
- 감수한 점: 스냅샷은 '마지막 새로 고침' 기준이라 화면에 기준일(`as_of`)을 함께 보인다. B-tree 48MB 추가 저장공간.
  쓰기마다 인덱스 갱신 비용 — 적재는 하루 1번 배치라 허용.
